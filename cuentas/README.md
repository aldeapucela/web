# Cuentas abiertas

Página estática Jekyll en `/cuentas/`; consulta directamente la vista pública de NocoDB, sin credenciales. La vista debe filtrar exclusivamente movimientos reales, definitivos y con justificantes revisados para publicación. La API es pública por sí misma: revisar los documentos antes de subirlos o exponerlos en la vista, nunca confiar en el frontend para proteger datos personales.

Campos observados: `Id`, `Concepto`, `Fecha` (AAAA-MM-DD), `Importe` (euros positivos con máximo dos decimales), `Tipo` (`Ingreso` o `Gasto`), `Categoria`, `Detalles`, `Justificante`, `Created time`, `Last modified time` y `Proovedor` (grafía exacta en la API). `Categoria` no se utiliza para inferir comisiones. El ingreso representa el importe recibido, que puede ser neto; no hay campos fiables para calcular recaudación bruta o comisiones. Los gastos de comisión registrados como gasto se suman una sola vez. No registrar como gastos separados comisiones ya descontadas de un ingreso neto. Saldo = ingresos recibidos − gastos registrados. Todos los movimientos deben usar la misma unidad y criterio contable y no duplicar transferencias y aportaciones que representen el mismo dinero.

La última actualización general es el máximo de `Last modified time` entre todos los movimientos recuperados; se oculta si falta o no se reconoce alguna fecha, para no presentar un dato incompleto. En cada detalle se muestra la fecha de modificación del registro si está disponible. Los instantes se presentan en la zona horaria de Madrid; `Fecha` sigue siendo la fecha del movimiento.

No existe campo de estado: la vista debe excluir previsiones, pendientes y registros no publicados. La página muestra los registros de la vista, incluidos los de prueba y los que tengan fecha futura; la fecha no determina si un movimiento está pendiente. Los tipos desconocidos y registros inválidos impiden mostrar totales en lugar de producir cifras incompletas.

La paginación usa `limit` y `offset` y comprueba `pageInfo.isLastPage`. La vista pública permite CORS `*`. El campo `Detalles` admite un subconjunto seguro de Markdown: párrafos, listas, negrita, cursiva, tachado, código y enlaces HTTP(S). Las etiquetas de salto `<br>` se convierten en saltos de línea; el resto del HTML y las imágenes no se interpretan; los enlaces se construyen como nodos y se abren en otra pestaña. Para adjuntos se usa la URL firmada actual devuelta por NocoDB (`signedUrl` o `signedPath`, o `url`), sin guardarla; se renueva en cada consulta. No había archivos adjuntos en la vista durante la implementación, por lo que su estructura concreta y su acceso anónimo deben verificarse con un documento inocuo y revisado antes de activar esa función en producción.

Los detalles se pueden compartir mediante `/cuentas/?id=ID`, donde `ID` es el identificador público de NocoDB. El diálogo se abre tras cargar los datos; si el movimiento ya no está en la vista se indica que no se ha encontrado.
